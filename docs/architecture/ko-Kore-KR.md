# 아키텍처와 구현 세부 사항

이 문서는 Linker가 어떻게 구현됐는지 설명합니다: 설계 목표와 전체 아키텍처, 데이터 모델, 다국어 메커니즘, 실시간 협업, 프런트엔드 계층 구조와 핵심 메커니즘. 코드를 읽거나 2차 개발을 하기 전에 여기를 먼저 보면 전체 그림을 더 빨리 잡을 수 있습니다.

함께 보는 문서:

- [API 인터페이스 문서](../api/ko-Kore-KR.md): 대외 계약의 전체 사양——REST 엔드포인트, WebSocket 브로드캐스트 메시지, 오류 코드 총표. 프런트엔드와 백엔드가 어떻게 통신하는지는 이 문서가 기준입니다
- [README](../../README.ko-Kore-KR.md): 제품 소개, 기능 목록과 빠른 시작(사용만 하려면 여기로 돌아가기)

## 용어집

한 줄에 정의 하나씩, 모호함을 없애기 위한 것입니다. 메커니즘 세부 사항은 본문 각 절을 기준으로 합니다.

| 용어 | 정의 |
|---|---|
| 조직 | 트리 구조 노드, 신분과 하위 조직을 포함할 수 있음([데이터 모델](#데이터-모델) 참조) |
| 신분 | 조직 안에서 정의한 역할(반장, 회원 같은), **직책이 아님**. 언어 간 번역에서는 직책류 단어를 금지 |
| 인물 | 전역 평면 엔티티로, 「보유」로 신분에 걸림 |
| 보유 | 신분-인물의 다대다 연결(`identity_person` 행) |
| 관계 | 두 보유 사이의 연결선(`person_person`)으로, forward/backward 양방향 라벨을 가짐 |
| 배정 | 보유를 만드는 동작. 「생성하고 배정」 = 인물을 만드는 동시에 보유를 만드는 것 |
| 데이터베이스 | 하나의 `.db` 파일, 즉 독립된 데이터베이스 하나로, 한 벌의 전체 그래프를 담음 |
| 기준 언어 | 데이터베이스 단위 설정으로, 이름의 기준 언어. 기준 슬롯은 반드시 비어 있지 않아야 하며, 폴백 체인의 종점임([다국어 데이터 모델](#다국어-데이터-모델) 참조) |
| 사용 언어 | 데이터베이스 단위 설정(정렬된 목록)으로, 이름 양식에 입력할 수 있는 언어와 내보내기 JSON의 언어 열을 결정 |
| 화면 언어 | 순수 프런트엔드 취향으로, 표시에만 영향. 데이터베이스별로 기억하고, 기본값은 기준 언어를 따름 |
| 언어 슬롯 | `_l10n` 부속 테이블에서 어떤 언어의 열 하나. `NULL` = 미번역 |
| 폴백 체인 | 표시 이름 찾기 순서: 화면 언어 슬롯 → 언어별 폴백 목록(순서대로, 사용 언어만. zh 3개 변체는 서로, en 2개 변체는 서로를 보완) → 기준 언어 슬롯 |
| 빈칸 규칙 | 기준 언어를 바꾼 뒤 기존 레코드가 새 기준 언어 아래에 값이 없는 상태. 다음에 편집할 때 반드시 그 자리에서 채워 넣어야 함 |
| 낙관적 업데이트 | 화면 조작을 먼저 로컬 캐시에 반영해 다시 그리고, 백그라운드에서 동기화하며, 실패하면 롤백 후 다시 받아옴 |
| 임시 키 / domKey | 아직 저장되지 않은 새 객체의 Symbol 키 / `tmp-N` DOM 식별자로, 저장되면 adoptId가 진짜 id를 다시 넣어줌([협업 메커니즘](#협업-메커니즘) 참조) |

## 설계 목표

- **제로 의존성**: Node 내장 `node:sqlite` + `node:http`만 쓰고, 프런트엔드는 네이티브 ES Module이라 빌드 단계가 없음——clone해 온 뒤 `node server.js`로 바로 실행 가능하며, 배포 시 외부 노출면이 없음
- **다중 데이터베이스**: `data/` 아래 각 `.db`는 독립된 데이터베이스로, 이름별로 지연 로딩하고 연결을 캐시함. 데이터베이스끼리는 완전히 격리되며, 백업/마이그레이션은 파일 하나면 됨
- **오프라인 우선(낙관적 업데이트)**: 화면 조작을 먼저 로컬 캐시에 반영하고 다시 그린 뒤, 요청은 백그라운드에서 동기화함. 실패하면 자동으로 롤백하고 다시 받아오며, 사용자는 네트워크 속도에 얽매이지 않음
- **협업**: REST 쓰기 성공 후 WebSocket으로 같은 데이터베이스의 다른 클라이언트에게 변경을 브로드캐스트하며, 발신자는 클라이언트 id로 루프백을 제외함
- **데이터 다국어는 1급 시민**: 이름에는 「주 언어 열」개념이 없고, 일률적으로 언어별 슬롯에 저장하며, 기준 언어는 폴백 체인의 종점일 뿐임

## 전체 아키텍처와 요청 생명주기

```
브라우저 ──HTTP──▶ server.js ──┬── 정적 파일(public/, 홈과 데이터베이스 페이지 포함)
                              ├── REST /:데이터베이스명/api/* ──▶ db.js(쓰기 메서드가 wrapDbForCollab으로 래핑됨)
                              └── WS   /:데이터베이스명/ws      ──▶ ws.js 브로드캐스트
```

쓰기 한 번의 경로: 프런트엔드 data.js가 먼저 로컬 캐시를 바꾸고 다시 그림(낙관적), 이어서 `X-Lang` / `X-Client-Id` 헤더를 달고 REST 요청을 보냄. 서버에서는 `wrapDbForCollab`으로 래핑된 db 메서드가 성공하면 곧바로 `OP_BUILDERS` 매핑대로 변경 메시지를 브로드캐스트함(발신자 제외). 프런트엔드는 브로드캐스트를 받으면 원격 변경을 로컬 캐시에 미러링함. 동기화 실패 시 롤백(전량 다시 받아오기)하며, 충돌은 합치지 않음——같은 리소스의 동시 쓰기는 마지막 것이 유효.

## 데이터 모델

기본 키는 일률적으로 UUID이며 백엔드가 생성함. 주 테이블에는 구조와 외래 키만 저장하고, **모든 이름은 `_l10n` 부속 테이블**에 있음(기준 슬롯은 비어 있지 않음이 보장됨, 아래 절 참조).

### 테이블 목록

| 테이블 | 열 | 설명 |
|---|---|---|
| `organization` | `id` PK · `parent_id` 자기 참조 · `created_at` · `sort_order` | 조직 트리 노드 |
| `identity` | `id` PK · `organization_id` → organization · `created_at` · `sort_order` | 조직 안의 신분 |
| `person` | `id` PK · `created_at` | 인물, 평면이라 트리가 아님 |
| `identity_person` | `person_id`+`identity_id` 복합 기본 키 · `created_at` · `sort_order` | 보유(다대다), 정렬은 신분 안에서만 |
| `person_person` | `id` PK · `a_person_id`/`a_identity_id`/`b_person_id`/`b_identity_id` · `created_at` | 관계, 양끝이 각각 하나의 「보유」 |
| `meta` | `id` PK · `value` | 메타 정보 키-값(`authoritative_lang` / `enabled_langs` / `bg_color` 등) |
| `organization_l10n` / `identity_l10n` / `person_l10n` | `id` PK → 주 테이블 · 언어별 열 | 이름 슬롯, 행 하나당 엔티티 하나 |
| `person_person_l10n` | `id`+`type`(forward/backward) 복합 기본 키 · 언어별 열 | 관계 양방향 라벨 슬롯 |
| `meta_l10n` | `id`(= meta 키) · 언어별 열 | 표시 이름(display_name)의 슬롯 |

언어 열은 `zh_Hans_CN` 같은 열 이름(언어 코드의 `-`를 `_`로 바꿈)이며, `NULL` = 해당 언어 미번역.

### 마이그레이션과 정렬

- **정렬 필드**: `sort_order`는 마이그레이션 `ensureSortColumn`이 organization / identity / identity_person에 채워 넣음(기존 데이터베이스는 rowid대로 채움). 동급 순서는 전체를 `reorderSiblings`로 다시 정렬함(하나를 고치면 열 전체를 다시 써서, 읽을 때 정렬을 생략하는 대가로)
- **언어 열 발전**: `ensureL10nColumns`가 다섯 장의 l10n 부속 테이블에 `LANGS`에 새로 들어온 언어 열을 채워 넣음——언어를 추가해도 테이블 구조 버전 번호를 바꾸지 않으며, 상시적인 발전임

### 연쇄 규칙

- 인물 삭제: 그 인물의 모든 보유와 끝점이 그 사람인 관계를 정리
- 조직 삭제: 기본값은 하위 트리 전체를 재귀 삭제. `promote=1`이면 하위를 남겨 삭제된 조직의 자리로 끌어올림
- 신분 삭제: 보유를 정리하고, 관계 끝점은 함께 이동해 재지정됨(`personPerson:retarget` 브로드캐스트에 전량 데이터 포함)

## 다국어 데이터 모델

세 언어 개념이 각자의 역할을 함:

| 개념 | 저장 위치 | 역할 |
|---|---|---|
| 기준 언어 | `meta.authoritative_lang`(데이터베이스마다 하나) | 이름의 기준 언어. 기준 슬롯은 반드시 비어 있지 않아야 하며, 표시 폴백 체인의 종점 |
| 사용 언어 | `meta.enabled_langs`(쉼표 문자열, 정렬됨) | 이름 양식에 어떤 언어를 입력할 수 있는지와 내보내기 JSON에 어떤 열이 들어가는지 결정. 기준 언어를 반드시 포함하며 항상 첫 자리 |
| 화면 언어 | 프런트엔드 localStorage(`linker:locale` 전역 + `linker:view:<경로>` 데이터베이스별 덮어쓰기) | 표시에만 영향을 주며 데이터베이스에는 들어가지 않음 |

**표시 폴백 체인**: 화면 언어 슬롯 → 언어별 폴백 목록(순서대로, 사용 언어의 슬롯만 시도. 예: zh-Hant-HK→zh-Hant-TW→zh-Hans-CN 이 서로 보완하고, en-Latn-GB와 en-Latn-US도 서로 보완) → 기준 언어 슬롯 →(빈 문자열 폴백은 호출 쪽이 처리). 프런트엔드 캐시가 모든 슬롯을 들고 있어서, 화면 언어 전환은 순수 메모리 재해석(`reresolveAll`)이며 백엔드를 건드리지 않음. 사용 언어 집합 전환도 마찬가지로 전량 재해석을 일으킴(폴백 체인의 사용 가능한 노드가 그에 따라 변화).

**쓰기 의미론**: 쓰기 인터페이스는 통일해서 `{authoritative, value, l10n}` 상위 집합 + `X-Lang` 헤더를 받음——

- 생성(`createPayload`): `authoritative`가 없으면 `value`로 폴백. 기준 슬롯은 최종적으로 반드시 비어 있지 않아야 하며, 아니면 `authoritative_required`
- 갱신(`namePatch`): `l10n`을 슬롯별로 upsert하며, **빈 문자열은 슬롯을 비움**(기준 슬롯은 예외, 기준 슬롯 비우기는 거부됨)
- 데이터베이스 생성 시 생성자의 `X-Lang`으로 기준 언어 씨앗값을 만듦. 기존 데이터베이스 마이그레이션 시에는 일률적으로 zh-Hans-CN으로 정함(일회성, 이미 실행 완료)

**빈칸 규칙**: 기준 언어를 바꾼 뒤에는 기존 레코드가 새 기준 언어 아래에 이름이 아직 없음(표시는 기존 기준값으로 폴백). 다음에 그 레코드를 편집할 때 반드시 그 자리에서 기준값을 채워 넣어야 저장할 수 있음.

양식 표시 형태(단일 입력 / 기준 + 현재 / 사용 언어 전체)는 프런트엔드의 「텍스트 입력」스위치가 결정하며, 쓰기 인터페이스에는 영향이 없음——인터페이스 계약은 [api 문서](../api/ko-Kore-KR.md) 참조.

## 협업 메커니즘

- **낙관적 업데이트**: `data.js`의 모든 op는 먼저 로컬 캐시를 바꾸고 `notify`로 다시 그린 뒤, 백그라운드에서 `api()`를 호출함. 실패하면 `loadAll()`으로 전량 다시 받아와 롤백
- **임시 키(tempKey)**: 아직 저장되지 않은 새 객체는 key로 Symbol을 쓰고, 동시에 `domKey`를 등록함(`tmp-N` 문자열로, DOM 속성과 색상 값 해시에 사용). 서버가 진짜 id를 돌려주면 `adoptId`로 다시 넣어주고, 트리 안 보유 항목의 id/l10n도 함께 맞춤(아니면 chip의 색상 선택과 언어 재해석이 플레이스홀더 값에 머무름)
- **브로드캐스트**: `ws.js`는 RFC 6455 부분 집합(텍스트 브로드캐스트 + ping/pong + 하트비트). 쓰기 메서드 → 메시지는 `OP_BUILDERS`가 매핑하며, 쓰기 한 번으로 여러 메시지가 나올 수 있음(예: 보유 옮기기 = assign + unassign + retarget 여러 개). 모든 op와 필드는 [api 문서](../api/ko-Kore-KR.md) 참조
- **충돌 정책**: 합치지 않고, last-write-wins. 다른 사람의 삭제가 내가 편집 중인 객체에 닿으면 편집 모드를 강제로 종료함(모달 스택을 비움)

## 프런트엔드 아키텍처

계층 데이터 흐름: `events.js`(전역 이벤트 프록시) → `controls.js` / `data.js`(동작과 데이터) → `html.js`(순수 함수가 HTML/SVG 텍스트 생성) → `view.js`(DOM 마운트). 렌더링 계층은 무상태이며, 상태는 세 종류:

| 상태 | 위치 | 설명 |
|---|---|---|
| 데이터 캐시 `store` | `data.js` | 조직 트리, 인물, 관계, meta의 전량 미러 |
| 뷰 상태 `vs` | `view.js` | 확대/초점/접기를 데이터베이스별로 `linker:view:<경로>`에 영속화 |
| 취향 설정 | `settings.js` / localStorage | 텍스트 입력 스위치 등 순수 로컬 취향 |

화면 항목은 `i18n.js`로 조회하며(항목이 없으면 키 자체를 표시), 정적 문구는 `data-i18n` 표시로 `applyStatic()`이 일괄 전환함. `head`의 인라인 스크립트는 항목이 준비되기 전까지 페이지를 잠시 숨겨 깜빡임을 방지함.

## 양식과 내보내기 세부 사항

- **이름 양식 형태**: bare/dual의 현재 행은 모두 화면 언어가 사용 언어 집합에 포함되어야 함. 포함되지 않으면 모든 형태가 「레이블이 붙은 기준 단일 입력」으로 수렴함. 그 외의 형태는 「텍스트 입력」셋 중 하나 선택 스위치로 결정——bare(단일 입력) / dual(기준 + 현재) / full(사용 언어 전체). 기준 행은 항상 첫 번째로, 굵게 표시되며, 필수이고 비울 수 없음. 생성 시와 기준 슬롯이 비어 있는 편집은 기준 행을 강제로 표시

| 화면 언어 | 사용 언어 | 기준 언어 | 기준 슬롯 비어 있음 | 옵션1 | 옵션2 | 옵션3 | 시나리오 |
|---|---|---|---|---|---|---|---|
| A | A 포함 | A | 예 | A, 레이블 없음 | A, 레이블 없음 | 전체, 레이블 있음 | 일반 생성 |
| A | A 포함 | A | 아니오 | A, 레이블 없음 | A, 레이블 없음 | 전체, 레이블 있음 | 일반 편집 |
| A | A 포함 | B | 예 | B와 A, 레이블 있음 | B와 A, 레이블 있음 | 전체, 레이블 있음 | 다국어 생성 또는 빈칸 규칙 기간 편집 |
| A | A 포함 | B | 아니오 | A, 레이블 없음 | B와 A, 레이블 있음 | 전체, 레이블 있음 | 다국어 편집 |
| A | A 미포함 | B | 예 | B, 레이블 있음 | B, 레이블 있음 | 전체, 레이블 있음 | 비표준 생성 |
| A | A 미포함 | B | 아니오 | B, 레이블 있음 | B, 레이블 있음 | 전체, 레이블 있음 | 비표준 편집 |

구현은 settings.js nameModalMode 참조
- **제목 팝업**(데이터베이스 표시 이름): 텍스트 입력 스위치 영향 없음, 기준 개념 없음, 굵게 표시하지 않음. 다국어 표시 시 현재 언어가 첫 번째이고, 어떤 언어라도 비어 있으면 데이터베이스 이름으로 폴백하며, 입력란 placeholder는 데이터베이스 이름값임. 제출 시 authoritative를 쓰지 않음
- **입력 검증 피드백**: 필수 항목이 비어 있으면 → 해당 입력란 빨간 테두리 + 자동 포커스, 하단에 가벼운 알림이 떠올랐다가 자동으로 사라지며, 조용히 거부하지 않음
- **내보내기 파일 이름**(PNG/SVG): `브랜드명_표시이름_타임스탬프.ext`, 브랜드명은 화면 언어를 따름. 「현재」 뷰 내보내기에는 조직 이름을 덧붙임
- **모바일**: 입력란 ≥16px, iOS 포커스 확대 방지

## 오류 규약

백엔드는 오류 코드만 반환함(`{error: code}`, 예: `org_not_found`). 오류 문구는 프런트엔드 l10n 항목(`error.*`)이 화면 언어로 관리함. 기준 슬롯 필수, 비우기 금지 같은 검증의 오류 코드는 `authoritative_required`, `authoritative_lang_invalid`임. 전체 오류 코드 표는 [api/ko-Kore-KR.md](../api/ko-Kore-KR.md) 참조.

public/
  index.html     데이터베이스 페이지 골격(헤더/사이드바/캔버스 컨테이너, data-i18n 표시, 깜빡임 방지 인라인 스크립트)
  home.html      새 데이터베이스 생성 홈(루트 경로 /, 정적 페이지)
  home.js        홈 스크립트: 언어 전환 + 양식 오류 알림(i18n 프레임워크 재사용)
  home.css       홈 스타일
  html.js        순수 함수 계층: HTML/SVG 텍스트와 좌표 등록(레이아웃, 캔버스, 패널, 메뉴/팝업 내용)
  view.js        뷰 계층: DOM 마운트, 뷰 상태(확대/초점/접기), 데이터베이스별 뷰 기억
  controls.js    팝업 컨트롤 통합 관리: 우클릭 메뉴 / 내보내기 드롭다운(2차 하위 메뉴 포함) / 모달(이름, 관계, 배경색, 확인) / 언어 팝업과 사용 언어 오버레이

  data.js        데이터 계층: 백엔드 통신, 낙관적 업데이트, 임시 키 메커니즘, 데이터 다국어 해석과 재해석, 원격 변경 미러
  export.js      내보내기 구현: PNG/SVG 이미지 조립, JSON/DB 다운로드, 파일 이름
  settings.js    텍스트 입력 모드(셋 중 하나만, 상호 배타, 필수 선택)와 이름/관계 팝업 형태 결정. 스위치는 localStorage에 저장(요청 본문 형태 결정)
