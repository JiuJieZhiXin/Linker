# アーキテクチャと実装の詳細

このドキュメントは Linker の実装について説明します。設計目標と全体アーキテクチャ、データモデル、多言語の仕組み、リアルタイムコラボレーション、フロントエンドの層構造と主要機構です。コードを読む前、二次開発を始める前にここを先に読めば、全体像がつかみやすくなります。

- [README](../../README.ja-Jpan-JP.md)：製品の紹介、機能一覧、クイックスタート（使うだけならこちらへ）

## 用語集

1行に1定義。曖昧さの解消用です。機構の細部は本文の各節を正とします。

| 用語 | 定義 |
|---|---|
| 組織 | ツリー構造のノード。身分と子組織を含められます（[データモデル](#データモデル)を参照） |
| 身分 | 組織内で定義される役割（部長や会員など）。**役職ではありません**。言語をまたぐ翻訳では役職類の語を禁じます |
| 人物 | グローバルなフラットな実体。「配属」を介して身分に結びつきます |
| 配属 | 身分ー人物の多対多の関連付け（`identity_person` の行） |
| 関係 | 2つの配属を結ぶ線（`person_person`）。forward/backward の双方向ラベルを持ちます |
| 割り当て | 配属を作成する操作。「新規作成して割り当て」＝ 人物の作成と同時に配属を作成すること |
| データベース | 1つの `.db` ファイル。独立した1つのデータベースで、1セットの完全なグラフを格納します |
| 作準言語 | データベースレベルの設定。名前の基準言語。作準スロットは非空が保証され、フォールバックチェーンの終点です（[多言語データモデル](#多言語データモデル)を参照） |
| 有効言語 | データベースレベルの設定（順序付きリスト）。名前フォームで入力できる言語と、エクスポート JSON の言語列を決めます |
| 表示言語 | フロントエンドだけの環境設定で、表示にのみ影響します。データベースごとに記憶され、デフォルトは作準言語に追従します |
| 言語スロット | `_l10n` 付属表における各言語の列。`NULL` ＝ 未翻訳 |
| フォールバックチェーン | 表示名の検索順序：表示言語スロット → 言語ごとのフォールバックリスト（順序どおり、有効言語のみ。zh の3変体は相互に、en の2変体も相互にバックアップし合う）→ 作準言語スロット |
| 穴埋め | 作準言語の切り替え後、既存レコードは新しい作準言語の下では値を持たず、次回の編集時にその場で補填が必須になります |
| 楽観的更新 | 操作を先にローカルキャッシュへ反映して再描画し、バックグラウンドで同期、失敗時はロールバックして再取得します |
| 一時キー / domKey | 未落庫の新規オブジェクトの Symbol キー ／ DOM 識別用の `tmp-N` 文字列。落庫後に adoptId が実 id に差し戻します（[コラボレーション機構](#コラボレーション機構)を参照） |

## 設計目標

- **ゼロ依存**：Node ビルトインの `node:sqlite` ＋ `node:http` のみ。フロントエンドはネイティブ ES Module でビルドステップなし——clone して `node server.js` だけで動き、デプロイに外部接面がありません
- **マルチデータベース**：`data/` 下の各 `.db` は独立したデータベースで、名前で遅延ロードして接続をキャッシュします。データベース間は完全に隔離され、バックアップ／移行は1つのファイルです
- **オフライン優先（楽観的更新）**：操作を先にローカルキャッシュへ反映して再描画し、リクエストはバックグラウンドで同期します。失敗時は自動でロールバックして再取得し、ユーザーをネットワークの速度に縛りません
- **コラボレーション**：REST 書き込みが成功すると、WebSocket を経て同じデータベースの他のクライアントへ変更をブロードキャストします。発起者はクライアント id で除外され、ループしません
- **データの多言語は一等公民**：名前に「主言語の列」という概念はなく、すべて言語ごとのスロットに格納します。作準言語はフォールバックチェーンの終点にすぎません

## 全体アーキテクチャとリクエストライフサイクル

```
ブラウザ ──HTTP──▶ server.js ──┬── 静的ファイル（public/。トップページとデータベースページを含む）
                           ├── REST /:データベース名/api/* ──▶ db.js（書き込みメソッドは wrapDbForCollab でラップ）
                           └── WS   /:データベース名/ws      ──▶ ws.js がブロードキャスト
```

1回の書き込みの経路：フロントエンド data.js が先にローカルキャッシュを更新して再描画（楽観的）し、続けて `X-Lang` / `X-Client-Id` ヘッダーを付けて REST リクエストを送ります。サーバーサイドでは `wrapDbForCollab` でラップされた db メソッドの実行成功が、`OP_BUILDERS` マップに従った変更メッセージのブロードキャスト（発起者を除く）になります。フロントエンドはブロードキャストを受けると、リモートの変更をローカルキャッシュへミラーします。同期に失敗した場合はロールバック（全量の再取得）し、競合はマージしません——同一リソースへの同時書き込みは最後の1回が有効です。

## データモデル

主キーはすべて UUID で、バックエンドが生成します。主テーブルは構造と外部キーだけを保持し、**すべての名前は `_l10n` 付属表**にあります（作準スロットの非空は保証。次節を参照）。

### テーブル一覧

| テーブル | 列 | 説明 |
|---|---|---|
| `organization` | `id` PK · `parent_id` 自己参照 · `created_at` · `sort_order` | 組織ツリーのノード |
| `identity` | `id` PK · `organization_id` → organization · `created_at` · `sort_order` | 組織内の身分 |
| `person` | `id` PK · `created_at` | 人物。フラットでツリーではありません |
| `identity_person` | `person_id`＋`identity_id` の複合主キー · `created_at` · `sort_order` | 配属（多対多）。並べ替えは身分内でのみ可能です |
| `person_person` | `id` PK · `a_person_id`/`a_identity_id`/`b_person_id`/`b_identity_id` · `created_at` | 関係。両端はそれぞれ1つの「配属」です |
| `meta` | `id` PK · `value` | メタ情報のキーバリュー（`authoritative_lang` / `enabled_langs` / `bg_color` など） |
| `organization_l10n` / `identity_l10n` / `person_l10n` | `id` PK → 主テーブル · 各言語列 | 名前スロット。1行＝1エンティティ |
| `person_person_l10n` | `id`＋`type`（forward/backward）の複合主キー · 各言語列 | 関係の双方向ラベルスロット |
| `meta_l10n` | `id`（＝ meta のキー）· 各言語列 | 表示名（display_name）のスロット |

言語列は `zh_Hans_CN` などの列名（言語コードの `-` を `_` に変換）で、`NULL` ＝ その言語は未翻訳です。

### マイグレーションと並べ替え

- **並べ替えのフィールド**：`sort_order` はマイグレーション `ensureSortColumn` によって organization / identity / identity_person に追加されます（既存データベースは rowid でバックフィル）。兄弟内の順序は全体として `reorderSiblings` で並べ直します（1件の変更で列全体を書き直し、読み取り時のソートをなくす代わりにします）
- **言語列の追加**：`ensureL10nColumns` は5枚の l10n 付属表に `LANGS` で新たに追加された言語列を補います——言語の追加はテーブル構造のバージョン番号を上げず、恒常的な更新です

### カスケードルール

- 人物の削除：すべての配属と、その人物を端点に持つ関係をクリアします
- 組織の削除：デフォルトでは子ツリーごと再帰削除します。`promote=1` の場合は下位を保持して、削除した組織の元の位置へ引き上げます
- 身分の削除：配属をクリアし、関係の端点は伴って移動しリダイレクトされます（`personPerson:retarget` ブロードキャストは全量データを持ちます）

## 多言語データモデル

3つの言語概念がそれぞれの役割を担います：

| 概念 | 格納先 | 役割 |
|---|---|---|
| 作準言語 | `meta.authoritative_lang`（データベースごとに1つ） | 名前の基準言語。作準スロットは非空が保証され、表示フォールバックチェーンの終点です |
| 有効言語 | `meta.enabled_langs`（コンマ区切り。順序あり） | 名前フォームで入力できる言語と、エクスポート JSON の言語列を決めます。作準言語を必ず含み、常に先頭に置きます |
| 表示言語 | フロントエンドの localStorage（`linker:locale` が全体 ＋ `linker:view:<パス>` がデータベースごとの上書き） | 表示にのみ影響します。データベースには入りません |

**表示フォールバックチェーン**：表示言語スロット → 言語ごとのフォールバックリスト（順序どおり、有効言語のスロットのみを試します。例：zh-Hant-HK→zh-Hant-TW→zh-Hans-CN が相互に、en-Latn-GB と en-Latn-US が相互にバックアップし合います）→ 作準言語スロット →（空文字列のフォールバックは呼び出し側が処理）。フロントエンドのキャッシュはすべてのスロットを保持し、表示言語の切り替えは純粋なメモリ内の再解析（`reresolveAll`）で、バックエンドにはアクセスしません。有効言語セットの切り替えも同様に全量の再解析を引き起こします（フォールバックチェーンの利用可能なノードがそれに伴って変わります）。

**書き込みの意味論**：書き込みインターフェースはすべて `{authoritative, value, l10n}` のスーパーセット ＋ `X-Lang` ヘッダーで受け取ります——

- 新規作成（`createPayload`）：`authoritative` は省略時に `value` にフォールバックします。作準スロットは最終的に非空が必須で、さもなければ `authoritative_required`
- 更新（`namePatch`）：`l10n` はスロットごとに upsert。**空文字列はスロットをクリア**（作準スロットは除く。作準スロットのクリアは拒否されます）
- データベース作成時は作成者の `X-Lang` を作準言語の種にします。既存データベースの移行時は一律 zh-Hans-CN に固定されました（1回限りで、実行済みです）

**穴埋めルール**：作準言語を切り替えると、既存レコードは新しい作準言語の下では一時的に名前を持たなくなり（表示は旧作準値にフォールバック）、次回そのレコードを編集するときは、作準値をその場で補わないと保存を許可しません。

フォームの表示形態（単一入力 ／ 作準＋現在 ／ 有効言語すべて）はフロントエンドの「テキスト入力」スイッチで決まり、書き込みインターフェースには影響しません——インターフェースの契約は [api ドキュメント](../api/ja-Jpan-JP.md)を参照してください。

## コラボレーション機構

- **楽観的更新**：`data.js` の各 op は先にローカルキャッシュを更新し `notify` で再描画してから、バックグラウンドで `api()` を呼び出します。失敗時は `loadAll()` で全量再取得してロールバックします
- **一時キー（tempKey）**：未落庫の新規オブジェクトは Symbol をキーにし、同時に `domKey`（`tmp-N` 文字列。DOM 属性と色のハッシュ計算に使用）を登録します。サーバーから実 id が返った後に `adoptId` が差し戻し、ツリー内の配属エントリの id/l10n も同期します（さもなければ chip の色取得と言語の再解析がプレースホルダーのまま止まります）
- **ブロードキャスト**：`ws.js` は RFC 6455 サブセット（テキストブロードキャスト ＋ ping/pong ＋ ハートビート）です。書き込みメソッド → メッセージは `OP_BUILDERS` でマップされ、1回の書き込みで複数件発生しえます（例：配属の移動 ＝ assign ＋ unassign ＋ retarget を複数件）。すべての op とフィールドは [api ドキュメント](../api/ja-Jpan-JP.md)を参照してください
- **競合の方針**：マージはせず、last-write-wins です。他者の削除が自分が編集中のオブジェクトに当たった場合は、編集モードを強制解除します（モーダルスタックを空にします）

## フロントエンドアーキテクチャ

層別データフロー：`events.js`（グローバルイベントデリゲート）→ `controls.js` ／ `data.js`（アクションとデータ）→ `html.js`（純粋関数が HTML/SVG テキストを生成）→ `view.js`（DOM をマウント）。レンダリング層はステートレスで、状態は3種類に分かれます：

| 状態 | 場所 | 説明 |
|---|---|---|
| データキャッシュ `store` | `data.js` | 組織ツリー、人物、関係、meta。サーバーサイドの全量ミラー |
| ビュー状態 `vs` | `view.js` | ズーム／フォーカス／折りたたみ。`linker:view:<パス>` にデータベースごとに永続化 |
| 環境設定 | `settings.js` ／ localStorage | テキスト入力スイッチなどの純粋にローカルな環境設定 |

画面の語句は `i18n.js` で検索され（語句がなければキー自体を表示）、静的な文言は `data-i18n` マークを付けて `applyStatic()` が一括で切り替えます。`head` 内のインラインスクリプトは、語句の準備が整うまでページを一時的に非表示にしてチラつきを防ぎます。

## フォームとエクスポートの詳細

- **名前フォームの形態**：bare/dual の現在行はいずれも、表示言語が有効言語セットに含まれていることを要求します。含まれない場合は、すべての形態が「ラベル付きの作準単一入力」に収斂します。それ以外は「テキスト入力」の3択スイッチで決まります——bare（単一入力）／ dual（作準 ＋ 現在）／ full（有効言語すべて）。作準行は常に先頭に並び太字で強調され、必須でクリアできません。新規作成と、作準スロットが空の編集では作準行の表示が強制されます

| 表示言語 | 有効言語 | 作準言語 | 作準スロットが空 | オプション1 | オプション2 | オプション3 | シナリオ |
|---|---|---|---|---|---|---|---|
| A | Aを含む | A | はい | A、ラベルなし | A、ラベルなし | 全部、ラベルあり | 通常の新規作成 |
| A | Aを含む | A | いいえ | A、ラベルなし | A、ラベルなし | 全部、ラベルあり | 通常の編集 |
| A | Aを含む | B | はい | BとA、ラベルあり | BとA、ラベルあり | 全部、ラベルあり | 多言語の新規作成または穴埋め期間中の編集 |
| A | Aを含む | B | いいえ | A、ラベルなし | BとA、ラベルあり | 全部、ラベルあり | 多言語の編集 |
| A | Aを含まない | B | はい | B、ラベルあり | B、ラベルあり | 全部、ラベルあり | 非標準の新規作成 |
| A | Aを含まない | B | いいえ | B、ラベルあり | B、ラベルあり | 全部、ラベルあり | 非標準の編集 |

実装は settings.js nameModalMode を参照
- **タイトルポップアップ**（データベースの表示名）：テキスト入力スイッチの影響を受けず、作準の概念もなく太字にもしません。多言語表示では現在言語が先頭に並び、どの言語を空にしてもデータベース名にフォールバックし、入力欄の placeholder はデータベース名の値です。送信時に authoritative は書き込みません
- **入力検証のフィードバック**：必須項目が空の場合 → 対応する入力欄に赤枠 ＋ 自動フォーカスし、下部に軽い通知が浮かんで自動で消えます。黙って拒否しません
- **エクスポートファイル名**（PNG/SVG）：`ブランド名_表示名_タイムスタンプ.ext`。ブランド名は表示言語に追従します。「現在」ビューのエクスポートには組織名が追加されます
- **モバイル**：入力欄は ≥16px で、iOS のフォーカスによるズームを防止します

## エラーの取り決め

バックエンドはエラーコードだけを返します（`{error: code}`。例：`org_not_found`）。エラーテキストはフロントエンドの l10n 語句（`error.*`）で表示言語ごとに管理します。作準スロットの必須・クリア禁止などの検証のエラーコードは `authoritative_required`、`authoritative_lang_invalid` です。完全なエラーコード表は [api ドキュメント](../api/ja-Jpan-JP.md)を参照してください。

```

db.js            SQLite データ層：テーブル作成（主テーブル ＋ l10n 付属表）、CRUD、カスケード削除、VACUUM スナップショット、マルチデータベースキャッシュ
ws.js            ミニマル WebSocket サーバー（RFC 6455 サブセット：テキストブロードキャスト ＋ ping/pong ＋ ハートビート）
public/
  index.html     データベースページの骨組み（ヘッダー／サイドバー／キャンバスコンテナ、data-i18n マーク、チラつき防止のインラインスクリプト）
  home.html      新規データベース作成のホームページ（ルートパス /。純粋な静的ページ）
  home.js        ホームページのスクリプト：言語切り替え ＋ フォームのエラー表示（i18n フレームワークを再利用）
  home.css       ホームページのスタイル
  html.js        純粋関数層：HTML/SVG テキストと座標の登記（レイアウト、キャンバス、パネル、メニュー／ポップアップの内容）
  view.js        ビュー層：DOM マウント、ビュー状態（ズーム／フォーカス／折りたたみ）、データベースごとのビュー記憶
  controls.js    ポップアップコントロールの統合管理：右クリックメニュー ／ エクスポートドロップダウン（2階層のサブメニュー付き）／ モーダル（名前、関係、背景色、確認）／ 言語ポップアップと有効言語オーバーレイ
  events.js      イベント層：グローバルデリゲート（ドラッグセッション、タッチジェスチャー、クリックルーティング、ホバーフォーカス、キーボード）
  data.js        データ層：バックエンド通信、楽観的更新、一時キー機構、データの多言語解析と再解析、リモート変更のミラーリング
  export.js      エクスポート実装：PNG/SVG 画像の組み立て、JSON/DB ダウンロード、ファイル名
  settings.js    テキスト入力モード（3択・排他・必須）と名前／関係ポップアップの形態決定。スイッチは localStorage に保存（リクエストボディの形態を決定）
  i18n.js        国際化フレームワーク：l10n 登録、t() の語句補間、localStorage 永続化、変更通知、applyStatic
  l10n/          表示言語の語句（語句がなければキー自体をフォールバック表示。10言語で同一のキーを揃える）
  collab.js      コラボレーション層：WebSocket 接続／再接続、リモート変更の配布
  style.css      スタイル（モバイル対応を含む）
```
