# البنية وتفاصيل التنفيذ

توضّح هذه الوثيقة كيف يُنفَّذ Linker: أهداف التصميم والبنية العامة، ونموذج البيانات، وآلية تعدد اللغات، والتعاون في الوقت الحقيقي، وطبقات الواجهة الأمامية وآلياتها الأساسية. اقرأها قبل قراءة الكود أو التطوير الثانوي لتكوّن صورة كلية أسرع.

الوثائق المرافقة:

- [وثائق واجهات API](../api/ar-SA.md): المواصفات الكاملة للعقد الخارجي — نقاط REST الطرفية، ورسائل بث WebSocket، وجدول رموز الأخطاء الكامل؛ والتواصل بين الواجهة الأمامية والخادم الخلفي يُرجَع فيه إليها
- &#x200F;[README](../../README.ar-SA.md): تعريف المنتج وقائمة الميزات والبدء السريع (لمن يريد الاستخدام فقط فليرجع إلى هنا)

## المصطلحات

تعريف واحد في كل سطر، لإزالة الالتباس؛ وتفاصيل الآليات في الأقسام أدناه.

| المصطلح | التعريف |
|---|---|
| منظمة | عقدة في بنية شجرية، يمكن أن تتضمّن صفات ومنظمات فرعية (انظر [نموذج البيانات](#نموذج-البيانات)) |
| صفة | دور معرَّف داخل المنظمة (نمط الوزير أو العضو)، **وليس منصبًا**؛ وتُحظَر في ترجمته عبر اللغات ألفاظ المناصب |
| شخص | كيان عالمي مسطّح، يُربَط بالصفة عبر «الارتباط» |
| ارتباط | ارتباط متعدد-إلى-متعدد بين الصفة والشخص (صفوف `identity_person`) |
| علاقة | خط بين ارتباطين (`person_person`)، بوسمين للاتجاهين forward/backward |
| إسناد | فعل إنشاء الارتباط؛ «إنشاء وإسناد» = إنشاء الشخص وإنشاء الارتباط معًا في آنٍ واحد |
| قاعدة | ملف `.db` واحد، أي قاعدة بيانات مستقلة، تضمّ مخططًا كاملًا للرسم |
| اللغة المرجعية | إعداد على مستوى القاعدة، لغة الأساس للأسماء؛ ويجب ألا تكون خانة المرجعية فارغة، وهي نهاية سلسلة الاحتياط (انظر [نموذج البيانات متعدد اللغات](#نموذج-البيانات-متعدد-اللغات)) |
| اللغات المفعّلة | إعداد على مستوى القاعدة (قائمة مرتّبة)، يحدّد اللغات التي يمكن تسجيل الأسماء بها في النماذج والأعمدة اللغوية في JSON التصدير |
| لغة الواجهة | تفضيل محض في الواجهة الأمامية، يؤثر على العرض فقط؛ يُحفَظ لكل قاعدة، وافتراضيًا يتبع اللغة المرجعية |
| خانة اللغة | عمود لإحدى اللغات في الجدول الملحق `_l10n`؛ `NULL` = غير مترجم |
| سلسلة الاحتياط | ترتيب البحث عن اسم العرض: خانة لغة الواجهة → خانة اللغة المرجعية |
| سدّ الفراغ | بعد تبديل اللغة المرجعية تبقى السجلات القديمة بلا قيمة باللغة المرجعية الجديدة، وعند تحريرها في المرة التالية يجب استكمال قيمة المرجعية في حينها |
| التحديث التفاؤلي | تنفيذ إجراء الواجهة على ذاكرة التخزين المحلية أولًا مع إعادة الرسم، ثم المزامنة في الخلفية، والتراجع بإعادة الجلب عند الفشل |
| مفتاح مؤقت / domKey | مفتاح Symbol للكائن المنشأ غير المخزّن بعد / معرّف DOM بصيغة `tmp-N`، وعند التخزين تُعاد كتابة المعرّف الحقيقي عبر adoptId (انظر [آلية التعاون](#آلية-التعاون)) |

## أهداف التصميم

- **صفر تبعيات**: `node:sqlite` و`node:http` المدمجان في Node فقط، والواجهة الأمامية ES Module أصيلة دون خطوة بناء — يكفي استنساخ المستودع وتشغيل `node server.js` للعمل، ولا يوجد أي سطح خارجي عند النشر
- **قواعد متعددة**: كل ملف `.db` في `data/` قاعدة مستقلة، تُحمَّل بالاسم عند الطلب وتُخزَّن اتصالاتها مؤقتًا؛ والعزلة بين القواعد تامة، والنسخ الاحتياطي/الترحيل مجرد نسخ ملف
- **دون اتصال أولًا (التحديث التفاؤلي)**: ينفَّذ إجراء الواجهة على ذاكرة التخزين المحلية أولًا مع إعادة الرسم، وتُزامَن الطلبات في الخلفية؛ وعند الفشل يتراجع الوضع تلقائيًا بإعادة الجلب الكامل، فلا يُقيَّد المستخدم بإيقاع الشبكة
- **التعاون**: بعد نجاح الكتابة عبر REST يبثّ الخادم التغييرات عبر WebSocket إلى عملاء القاعدة نفسها الأخرين، ويستبعد المُرسِل من الرسالة الراجعة بحسب معرّف العميل
- **تعدد لغات البيانات مواطن من الدرجة الأولى**: لا وجود لمفهوم «عمود اللغة الرئيسية» للأسماء، فتُخزَّن جميعها في خانات لغوية، واللغة المرجعية ليست سوى نهاية سلسلة الاحتياط

## البنية العامة ودورة حياة الطلب

```
المتصفح ──HTTP──▶ server.js ──┬── الملفات الثابتة (public/، بما فيها الصفحة الرئيسية وصفحة القاعدة)
                              ├── REST /:اسم_القاعدة/api/* ──▶ db.js (دوال الكتابة مغلّفة بـ wrapDbForCollab)
                              └── WS   /:اسم_القاعدة/ws      ──▶ ws.js للبثّ
```

مسار الكتابة الواحدة: تعدّل الواجهة الأمامية `data.js` ذاكرة التخزين المحلية أولًا وتعيد الرسم (تفاؤليًا)، ثم ترسل طلب REST حاملًا ترويسة `X-Lang` / `X-Client-Id`؛ وعند نجاح تنفيذ دالة db المغلّفة بـ `wrapDbForCollab` على الخادم يُرسَلت رسالة التغيير فورًا وفق خريطة `OP_BUILDERS` (باستثناء المُرسِل)؛ وتتلقّى الواجهة الأمامية البثّ فتُمرّر التغيير البعيد إلى ذاكرة التخزين المحلية. وعند فشل المزامنة يتراجع الوضع (إعادة جلب كاملة)، ولا يجري أي دمج للتعارضات — الكتابات المتزامنة على المورد نفسه تُقبَل بآخرها.

## نموذج البيانات

المفاتيح الأساسية كلها UUID تولّدها الواجهة الخلفية. وتخزّن الجداول الرئيسية البنية والمفاتيح الأجنبية فقط، **وجميع الأسماء في الجداول الملحقة `_l10n`** (مع ضمان عدم فراغ خانة المرجعية، انظر القسم التالي).

### قائمة الجداول

| الجدول | الأعمدة | الشرح |
|---|---|---|
| `organization` | `id` PK · `parent_id` مرجع ذاتي · `created_at` · `sort_order` | عقدة شجرة المنظمات |
| `identity` | `id` PK · `organization_id` → organization · `created_at` · `sort_order` | الصفة داخل المنظمة |
| `person` | `id` PK · `created_at` | الشخص، كيان مسطّح لا شجرة له |
| `identity_person` | مفتاح مركّب `person_id`+`identity_id` · `created_at` · `sort_order` | الارتباط (متعدد-إلى-متعدد)، والفرز داخل الصفة فقط |
| `person_person` | `id` PK · `a_person_id`/`a_identity_id`/`b_person_id`/`b_identity_id` · `created_at` | العلاقة، وكل طرف منها «ارتباط» |
| `meta` | `id` PK · `value` | أزواج مفاتيح القيم الوصفية (`authoritative_lang` / `enabled_langs` / `bg_color` وغيرها) |
| `organization_l10n` / `identity_l10n` / `person_l10n` | `id` PK → الجدول الرئيسي · أعمدة اللغات | خانات الأسماء، صف واحد لكل كيان |
| `person_person_l10n` | مفتاح مركّب `id`+`type`(forward/backward) · أعمدة اللغات | خانات وسمي العلاقة المزدوجي الاتجاه |
| `meta_l10n` | `id` (= مفتاح meta) · أعمدة اللغات | خانة اسم العرض (display_name) |

أسماء أعمدة اللغات بصيغة `zh_CN` (يُستبدل `-` في رمز اللغة بـ `_`)، و`NULL` = غير مترجم بتلك اللغة.

### الترحيل والفرز

- **عمود الفرز**: يضيف الترحيل `ensureSortColumn` عمود `sort_order` إلى organization / identity / identity_person (وتُملأ القيم في القواعد القديمة من rowid)؛ ويعيد `reorderSiblings` ترتيب الإخوة في المستوى الواحد كاملًا (تغيير سطر واحد يعيد كتابة العمود بأكمله، ثمنًا لقراءة بلا فرز)
- **تطوّر أعمدة اللغات**: يُكمل `ensureL10nColumns` أعمدة لغات `LANGS` الجديدة لخمسة جداول l10n ملحقة — فإضافة لغة لا تغيّر رقم إصدار بنية الجداول، بل تطوّر اعتيادي

### قواعد التسلسل

- حذف شخص: يمسح جميع ارتباطاته والعلاقات التي طرف من أطرافها
- حذف منظمة: يُحذف افتراضيًا الشجرة الفرعية بأكملها بشكل متسلسل؛ ومع `promote=1` تُحفَظ الفروع وتُرفَع إلى موضع المنظمة المحذوفة
- حذف صفة: يمسح ارتباطاتها، وتُعاد توجيه أطراف العلاقات تبعًا لذلك (بثّ `personPerson:retarget` يحمل البيانات كاملة)

## نموذج البيانات متعدد اللغات

ثلاثة مفاهيم لغوية، لكل منها وظيفته:

| المفهوم | موضع التخزين | الوظيفة |
|---|---|---|
| اللغة المرجعية | `meta.authoritative_lang` (واحدة لكل قاعدة) | لغة الأساس للأسماء؛ ويجب ألا تكون خانة المرجعية فارغة، وهي نهاية سلسلة الاحتياط للعرض |
| اللغات المفعّلة | `meta.enabled_langs` (سلسلة مفصولة بفواصل، مرتّبة) | تحدّد اللغات التي يمكن تسجيل الأسماء بها في النماذج والأعمدة اللغوية في JSON التصدير؛ ويجب أن تتضمّن اللغة المرجعية وأن تتصدّرها دائمًا |
| لغة الواجهة | localStorage في الواجهة الأمامية (`linker:locale` عمومًا + `linker:view:<المسار>` تجاوز لكل قاعدة) | تؤثر على العرض فقط، ولا تدخل قاعدة البيانات |

**سلسلة الاحتياط للعرض**: خانة لغة الواجهة → خانة اللغة المرجعية → (وأما الفراغ التام فيتولّى الاحتياط منه المستدعي). وتنطوي ذاكرة التخزين المحلية في الواجهة على جميع الخانات، فتبديل لغة الواجهة إعادة تحليل خالصة في الذاكرة (`reresolveAll`) دون لمس الخادم الخلفي.

**دلالات الكتابة**: تستقبل واجهات الكتابة بصورة موحّدة حمولة فائقة `{authoritative, value, l10n}` + ترويسة `X-Lang` —

- الإنشاء (`createPayload`): عند الغياب يعود `authoritative` إلى `value`؛ ويجب ألا تكون خانة المرجعية فارغة في النهاية وإلا `authoritative_required`
- التحديث (`namePatch`): يدمج `l10n` خانةً خانة (upsert)، **والسلسلة الفارغة تُفرّغ الخانة** (عدا خانة المرجعية، فإفراغها مرفوض)
- عند إنشاء القاعدة تُزرَع اللغة المرجعية من `X-Lang` للمنشئ؛ وقواعد المخزون عند ترحيلها ضُبطت جميعها على zh-CN (مرة واحدة، وأُنجزت)

**قاعدة سدّ الفراغ**: بعد تبديل اللغة المرجعية تبقى السجلات القديمة بلا اسم باللغة المرجعية الجديدة (فيعرض الاحتياطي القيمة المرجعية القديمة)، وعند تحرير السجل في المرة التالية يجب استكمال قيمة المرجعية في حينها وإلا مُنع الحفظ.

ويحدّد شكل عرض النموذج (إدخال واحد / مرجعي+حالي / جميع اللغات المفعّلة) مفتاح «الإدخال النصي» في الواجهة الأمامية، ولا يؤثر على واجهات الكتابة — وعقد الواجهة في [وثيقة api](../api/ar-SA.md).

## آلية التعاون

- **التحديث التفاؤلي**: كل عملية في `data.js` تعدّل ذاكرة التخزين المحلية أولًا وتستدعي `notify` لإعادة الرسم، ثم `api()` في الخلفية؛ وعند الفشل يتراجع الوضع بإعادة الجلب الكاملة `loadAll()`
- **المفتاح المؤقت (tempKey)**: الكائنات المنشأة غير المخزّنة بعد تُفتَح بمفتاح Symbol، ويُسجَّل معها `domKey` (سلسلة `tmp-N` لخاصيات DOM ولتجزئة اللون)؛ وبعد أن يعيد الخادم المعرّف الحقيقي تُعاد كتابته عبر `adoptId`، وتُزامَن حقولا id/l10n لبنود الارتباط داخل الشجرة (وإلا بقيت بصمة لون الشارة وإعادة تحليل اللغة على قيم العنصر النائب)
- **البثّ**: `ws.js` مجموعة جزئية من RFC 6455 (بثّ نصي + ping/pong + نبضات قلب)؛ وتتحدد رسالة الكتابة → الرسالة عبر خريطة `OP_BUILDERS`، وقد تُنتِج الكتابة الواحدة رسائل متعددة (فنقل الارتباط مثلًا = assign + unassign + عدد من retarget)، وجميع العمليات والحقول في [وثيقة api](../api/ar-SA.md)
- **استراتيجية التعارض**: لا دمج، وآخر كتابة تفوز؛ وإذا أصاب حذف الغير كائنًا تحرّره حاليًا فتُخرَج قسرًا من وضع التحرير (تُفرَّغ كومة النوافذ النمطية)

## بنية الواجهة الأمامية

تدفّق بيانات طبقي: `events.js` (الوكيل العام للأحداث) → `controls.js` / `data.js` (الإجراءات والبيانات) → `html.js` (دوال نقية تُنتج نصوص HTML/SVG) → `view.js` (تركيب DOM). طبقة العرض بلا حالة، والحالة ثلاثة أصناف:

| الحالة | الموضع | الشرح |
|---|---|---|
| ذاكرة التخزين `store` | `data.js` | شجرة المنظمات والأشخاص والعلاقات وmeta، مرآة كاملة للخادم |
| حالة العرض `vs` | `view.js` | تكبير/تركيز/طيّ، تُحفَظ لكل قاعدة في `linker:view:<المسار>` |
| التفضيلات | `settings.js` / localStorage | تفضيلات محلية خالصة كمفتاح «الإدخال النصي» |

وتُبحث مقاطع الواجهة عبر `i18n.js` (وعند غياب المقطع يُعرض المفتاح نفسه)، وتمرّ النصوص الثابتة بعلامات `data-i18n` لتُبدَّل دفعة واحدة عبر `applyStatic()`؛ وسكربت مضمَّن في `head` يخفي الصفحة مؤقتًا إلى حين جاهزية المقاطع منعًا للوميض.

## تفاصيل النماذج والتصدير

- **شكل نموذج الأسماء**: يحدّده مفتاح ثلاثي الخيارات «الإدخال النصي» — bare (إدخال واحد) / dual (مرجعي + حالي) / full (جميع اللغات المفعّلة)؛ وصف المرجعية يتصدّر دائمًا بخط عريض وهو إلزامي لا يُفرَّغ؛ والإنشاء الجديد وتحرير ما خانة مرجعيته فارغة يفرضان إظهار صف المرجعية
- **نافذة العنوان** (اسم عرض القاعدة): لا تتأثر بمفتاح الإدخال النصي، ولا مفهوم مرجعي فيها فلا خط عريض؛ وعند العرض متعدد اللغات تتصدّر اللغة الحالية، وأي لغة تُترك فارغة يعود الاحتياط فيها إلى اسم القاعدة، وplaceholder في مربع الإدخال هو قيمة اسم القاعدة؛ والإرسال لا يكتب authoritative
- **تغذية راجعة للتحقق من الإدخال**: فراغ خانة إلزامية → إطار أحمر لمربع الإدخال الموافق + تركيز تلقائي، وإشعار خفيف يطفو أسفل الشاشة ويختفي تلقائيًا، دون رفض صامت
- **اسم ملف التصدير** (PNG/SVG): بالنمط `علامة_معروض_طابع_زمني.ext`، وتتبع علامة المنتج لغة الواجهة؛ وتصدير عرض «الحالي» يُلحق اسم المنظمة
- **الجوال**: مربعات الإدخال ≥16px لمنع تكبير التركيز في iOS

## اتفاق الأخطاء

يردّ الخادم الخلفي رموز الأخطاء فقط (`{error: code}`، مثل `org_not_found`)، وتصاغ نصوص الأخطاء في مقاطع l10n للواجهة الأمامية (`error.*`) بحسب لغة الواجهة؛ ورمزا خطأ التحقق من إلزامية خانة المرجعية ومنع إفراغها هما `authoritative_required` و`authoritative_lang_invalid`. وجدول رموز الأخطاء الكامل في [api/ar-SA.md](../api/ar-SA.md).

db.js            طبقة بيانات SQLite: إنشاء الجداول (رئيسية + ملحقة l10n) والعمليات CRUD والحذف المتسلسل ولقطة VACUUM وتخزين القواعد المؤقت متعدد القواعد
